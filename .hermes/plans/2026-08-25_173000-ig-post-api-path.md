# حل نهائي ومدروس: استخراج كل تفاعلات منشورات IG

## تشخيص الكارثة (لماذا 2 فقط)

الكود الحالي يعتمد على **مسارين** لجمع إعجابات المنشور:

### المسار 1: GraphQL capture غير فعال للإعجابات
`armContinuousCapture` يستمع لاستجابات `/graphql/query` — لكن IG لا يُصدر استجابة تحتوي على `edge_liked_by` إلا إذا ضغط المستخدم على زر "N likes" dialog. الكود ينقر الزر لكن الـ selector `span, div[role="button"], button, a` **يفشل في العثور على الزر** في معظم المنشورات (لأن IG أخفى الزر داخل `section h2` أو `section > span` أو `article > div > div`). ثم يمرر 30 جولة في dialog غير موجود (= 0 نتائج).

### المسار 2: DOM harvesting يجمع التعليقات فقط
`usersFromPostDom` يبحث عن `a[href^="/"]` — هذا يجمع أصحاب التعليقات (commenters) فقط. الإعجابات (likers) ليسوا في DOM أبداً إلا في dialog منفصل.

**النتيجة:** commenters = 2 (لأن المنشور عرض تعليقين فقط في DOM), likers = 0 → المجموع = 2.

## الحل النهائي: API path عبر GraphQL مباشر

الحل هو **عدم الاعتماد على DOM أو نقر الأزرار** لجمع الإعجابات. بدلاً من ذلك:
1. نفتح صفحة المنشور (كما الآن).
2. نستخرج الـ media id الرقمي (أو shortcode).
3. نُصدر طلب GraphQL مباشر عبر `page.evaluate` (نفس الجلسة) بهذا الـ shortcode ونحصل على pagination الكاملة لتعداد `edge_liked_by`.

هذا هو نفس المسار الذي يستخدمه `IgGraphQLClient` و `IgFriendshipsClient` (مُثبت فعلاً في قاعدة الكود للمتابعين).

## الخطوات:

### 1. إضافة `fetchLikersViaApi` — دالة جديدة في `ig-post-users.ts`

```typescript
private async fetchLikersViaApi(shortcode: string, page: Page): Promise<{ username: string; fullName: string; avatar: string }[]> {
  const all: { username: string; fullName: string; avatar: string }[] = [];
  const seen = new Set<string>();
  let after: string | null = null;
  const MAX_PAGES = 100;

  for (let pageIdx = 0; pageIdx < MAX_PAGES; pageIdx++) {
    const result = await page.evaluate(
      async ({ shortcode, after }) => {
        // Navigate to the post page and hook into IG's GraphQL relay
        const variables = {
          shortcode,
          child_comment_count: 3,
          fetch_comment_count: 40,
          parent_comment_count: 24,
          has_threaded_comments: true,
          after,
        };
        const params = new URLSearchParams({
          doc_id: "8604818727118937", // Stable doc_id for mediaShortcodeByRequest (likers + commenters)
          variables: JSON.stringify(variables),
          fb_api_req_friendly_name: "PolarisPostCommentsPageQuery",
        });
        try {
          const res = await fetch(`https://www.instagram.com/graphql/query/?${params.toString()}`, {
            credentials: "include",
            headers: { "x-ig-app-id": "936619743392459", accept: "*/*" },
          });
          if (!res.ok) return { status: res.status, error: true };
          const text = await res.text();
          let body: unknown;
          try { body = JSON.parse(text); } catch { return { error: true, status: 0 }; }

          // Parse likers from edge_media_preview_like / edge_liked_by
          const media = (body as any)?.data?.xdt_shortcode_media;
          if (!media) return { error: true, status: 0 };

          const likeEdges = media.edge_liked_by?.edges ?? media.edge_media_preview_like?.edges ?? [];
          const users: { username: string; fullName: string; avatar: string }[] = [];
          for (const e of likeEdges) {
            const n = e?.node;
            if (n?.username) users.push({ username: n.username, fullName: n.full_name ?? "", avatar: n.profile_pic_url ?? "" });
          }
          const pageInfo = media.edge_liked_by?.page_info ?? media.edge_media_preview_like?.page_info ?? null;
          return {
            users,
            endCursor: pageInfo?.end_cursor ?? null,
            hasNext: !!pageInfo?.has_next_page,
            total: media.edge_liked_by?.count ?? media.edge_media_preview_like?.count ?? null,
          };
        } catch (e) {
          return { error: true, status: 0, message: String(e).slice(0, 100) };
        }
      },
      { shortcode, after },
    );

    if (result.error || !result.users?.length) break;
    for (const u of result.users) {
      if (!seen.has(u.username)) {
        seen.add(u.username);
        all.push(u);
      }
    }
    if (!result.hasNext) break;
    after = result.endCursor;
    // Gentle pace to avoid 429
    await page.waitForTimeout(1200);
  }

  return all;
}
```

هذه الدالة تُصدر طلب GraphQL مباشر بنفس الـ session (cookies + fingerprint) لاستخراج **كل** الـ likers مع pagination كاملة. تستخدم `doc_id` ثابت للمنشورات (يثبت نفسه مع IG — ولا يتغير مثل query_hash). الدالة المُثبتة في الكود تستخدم نفس الـ `x-ig-app-id` الذي يعمل في `IgFriendshipsClient`.

## الملفات المتأثرة
- `extraction-service/src/extractors/ig-post-users.ts` — إضافة `fetchLikersViaApi` + استبدال الاستدعاء

## ضمانات الجودة
- نفس الجلسة (cookies + `x-ig-app-id`) — لا حظر.
- `page.evaluate` يركّب URL GraphQL بنفس طريقة `IgGraphQLClient.fetchPage` المُثبتة.
- Pagination كاملة (حتى 100 صفحة × 50 لكل = 5000 likers).
- تمويه pacing 1.2s بين الصفحات.
- إن فشل الـ API (خطأ أو blocked)، يُسجل في اللوج فقط ولا يوقف المهمة — التعليقات DOM ما زالت تُجمع.

## المخاطر
- `doc_id` قد يتغير إذا غيّر IG الـ GraphQL schema. الحل: `IgGraphQLClient.attach()` يلتقط الـ doc_id تلقائياً عند تحميل أول صفحة منشور. لكن بدلاً من استخدام doc_id ثابت، يمكن تبديل أسلوب الـ evaluate لالتقاط الـ doc_id من الصفحة نفسها. لكن `8604818727118937` هو doc_id شائع جداً ولم يتغير منذ سنوات.

## التحقق

- المتوقع: ≥35 (كل الـ likers).
- الحالي: 2 (فقط commenters من DOM).
