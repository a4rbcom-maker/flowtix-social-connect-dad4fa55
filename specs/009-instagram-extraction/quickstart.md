# Quickstart: دليل التحقق من استخراج إنستجرام

**الغرض**: سيناريوهات تحقق قابلة للتشغيل تثبت عمل الميزة end-to-end. تفاصيل العقود في [contracts/api.md](./contracts/api.md) والبيانات في [data-model.md](./data-model.md).

## المتطلبات المسبقة

1. كوكيز إنستجرام صالحة من متصفح مسجّل فيه دخول (صيغة EditThisCookie JSON) — يجب أن تحوي `sessionid` + `ds_user_id` + `csrftoken`
2. الخدمة تعمل محلياً:

```bash
cd extraction-service && npm install && npm run dev   # port 3100
```

3. الـ migration مطبق على Supabase المحلي/السحابي: `supabase/migrations/2026081810_ig_extraction.sql`
4. حساب اختبار إنستجرام عام به 100+ متابع، ومنشور عام بتعليقات، وهاشتاج نشط

## فحوص البناء (تُشغَّل قبل كل سيناريو وبعده)

```bash
# جذر المشروع
npm run typecheck && npm run lint
# خدمة الاستخراج
cd extraction-service && npm run typecheck
```

المتوقع: صفر أخطاء في الأربعة.

## السيناريو 1 — استيراد جلسة والتحقق منها (US1)

```bash
curl -s -X POST http://localhost:3100/ig/sessions/import \
  -H "Content-Type: application/json" -H "X-API-Key: flowtix-extraction-2026" \
  -d '{"user_id":"<uuid>","name":"ig-test","cookies":[...]}'
```

- **المتوقع**: 200 مع `status: "connected"` و`ig_username` صحيح خلال ≤ 60 ثانية (SC-001)
- **سلبي**: كوكيز ناقصة → 400 `INVALID_COOKIES` برسالة عربية واضحة؛ كوكيز منتهية → session-check يعيد `disconnected`

## السيناريو 2 — متابعو حساب عام بتغطية (US2)

```bash
curl -s -X POST http://localhost:3100/extract \
  -H "Content-Type: application/json" -H "X-API-Key: flowtix-extraction-2026" \
  -d '{"session_id":"<ig-session-uuid>","type":"ig_followers","source_url":"https://instagram.com/<target>","max_results":8000,"skip_duplicates":true}'
```

- **المتوقع**: 202 مع job_id؛ المهمة تظهر في صفحة المهام خلال ≤ 5 ثوانٍ؛ progress يتحدث كل ≤ 15 ثانية ويشمل العدد الكلي ونسبة التغطية (SC-002/SC-003)
- **بعد الاكتمال**: نسبة التغطية ≥ 80% لحساب ≤ 10K متابع؛ النتائج في صفحة الجهات مع platform=instagram والفلترة تعمل
- **سلبي**: حساب خاص → رفض فوري برسالة تشرح السبب (FR-010)

## السيناريو 3 — جلسات متعددة بالتوازي (ملاحظة المستخدم)

نفس نداء السيناريو 2 مع `"session_ids": ["<uuid-1>","<uuid-2>"]`.

- **المتوقع**: الجلستان تعملان معاً، النتائج مدمجة بلا تكرار usernames، زمن الإنجاز أقصر (أو التغطية أعلى) من جلسة واحدة على نفس الهدف (SC-010)
- **سلبي**: إسقاط جلسة أثناء التشغيل (حظر) → استمرار الأخرى دون فقدان نتائج؛ حظر الكل → `paused` قابلة للاستئناف (FR-013)

## السيناريو 4 — معلّقو منشور (US3)

`type: "ig_post_commenters"`, `source_url: "https://instagram.com/p/<code>"`.

- **المتوقع**: كل المعلّقين المتاحين مع نصوص تعليقاتهم؛ المعلّق المتكرر يظهر مرة واحدة مع `comments_count`؛ عدّاد الإعجابات الظاهر يُخزن كمرجع (SC-004: صحة username/رابط ≥ 98%)
- **سلبي**: رابط محذوف → رسالة خطأ واضحة دون تعليق المهمة

## السيناريو 5 — هاشتاج بنتائج جزئية معلنة (US4)

`type: "ig_hashtag_posts"`, `source_url: "<tag>"`.

- **المتوقع**: منشورات وأصحابها + تنبيه "النتائج جزئية" ظاهر في تفاصيل المهمة والنتائج دائماً (SC-005)؛ صاحب متكرر يظهر مرة بعدد منشوراته
- **سلبي**: هاشتاج محظور → رسالة صريحة بالسبب

## السيناريو 6 — بيانات ملف + إثراء بشارة ثقة (US5 + US6)

1. `type: "ig_profile_info"` على username بـ bio يحوي بريداً/هاتفاً
2. انتظر ≤ 30 ثانية بعد الاكتمال ثم تحقق من نتائج المهمة عبر Supabase أو صفحة الجهات

- **المتوقع**: `bio_email`/`bio_phone` مستخلصان صحيحان (SC-006: ≥ 95%)؛ الإثراء بدأ تلقائياً؛ النتائج المطابقة عبر bio تحمل شارة "مؤكدة" والمطابقة بالاسم فقط "محتملة"؛ التصدير يحمل عمود `Match Confidence` (SC-009)

## السيناريو 7 — واجهة الاستخدام (frontend)

```bash
npm run dev   # port 5173
```

- **المتوقع**: صفحة "جلسات إنستجرام" وصفحة "استخراج إنستجرام" بالقائمة؛ إنشاء مهمة من الواجهة يمر بنفس مسارات السيناريوهات أعلاه؛ RTL سليم وكل النصوص مترجمة ar/en؛ واجهة الإنشاء **لا تعرض** أي خيار مستحيل (إعجابات/DMs/ستوري) (SC-008)
- **فحص الترجمة**: التبديل ar↔en لا يترك نصاً خاماً أو مكانياً

## فحوص عدم كسر الموجود (regression)

- تشغيل استخراج fb واحد (groups/pages/post_comments) بعد كل التغييرات → يعمل كما قبل، ونتائجه `platform=facebook` تلقائياً
- صفحة الجهات بلا فلتر تعرض المزيج؛ بالفلتر facebook تعرض fb فقط — لا يتغير أي سلوك قائم
